# 版本管理与备份约定

生效日期：2026-08-29。本约定用于日常升级与备份，防止改坏无法回滚、数据丢失。

## 一、版本管理（git + GitHub）

远程私有仓库：`https://github.com/jxg0115/forex-trading-system.git`（仅代码与文档）。

**每次升级的标准流程：**

```bash
# 1. 升级前：备份数据 + 打基线 tag
python tools/factor_export.py                      # 备份数据库 + 导出因子清单（见第三节）
git add -A
git commit -m "snapshot: before <本次升级说明>"
git tag v-<功能>-before                            # 例如 v-factors-v2-before
git push origin master --tags

# 2. 升级中：在副本 C:\Users\xg\Documents\外汇交易系统-dev 上实验（原项目不动）
#   验证通过后，把改动同步回主线目录

# 3. 升级后：提交 + 推送
git add -A
git commit -m "feat: <功能说明>"
git tag v-<功能>                                   # 例如 v-factors-v2
git push origin master --tags
```

**回滚：**
- 回到某个 tag：`git checkout v-xxx`（或看 diff：`git diff v-xxx-before..HEAD`）
- 远程与本地一致，回滚后记得 `git push --force`（仅在确认覆盖时用）

## 二、不进 git 的内容（.gitignore 已生效，勿破坏）

| 内容 | 原因 |
|---|---|
| `.env` | 含 MT5 账号 / API 密钥，敏感 |
| `data/*.db` | 数据库，走文件备份（第三节），不放 git |
| `runtime/` | 依赖环境（约 500MB，可再生） |
| `ui_layer/node_modules/`、`ui_layer/dist/` | 前端依赖与构建产物 |
| `ui_layer_v2/`、`package_dist/`、`build_pyinstaller/`、`tmp_analysis/` | 旧版/打包/临时产物 |
| `__pycache__/`、`.venv/`、`.idea/` 等 | 生成物 |

新增任何大目录/敏感文件前，先确认是否要加 .gitignore。

## 三、备份体系（三线）

1. **代码线**：git 本地历史 + GitHub 私有仓库（每轮升级都有 tag，可随时回退）。
2. **升级实验线**：副本 `C:\Users\xg\Documents\外汇交易系统-dev`（独立数据库，runtime 与 node_modules 复用链接，原项目不动）。
3. **数据线（因子/交易数据）**：`python tools/factor_export.py`，双轨输出：
   - DB 完整备份 → `C:\Users\xg\Documents\外汇交易系统-backups\factor_store_<时间戳>.db`
     （SQLite 在线备份 API，后端运行中也能安全执行；升级前、定期执行）
   - 因子/候选清单 → `exports\factors_<时间戳>.json`（factors 正式因子 + mining_candidates 挖掘候选全量字段）
     —— **随 git 提交推送 GitHub**，因子状态有历史、可对比、可回滚看。

**频率**：每次升级前必须执行一次；平时建议每周一次（数据线）。

## 四、常用命令备忘

```bash
git status                 # 看改动
git log --oneline          # 看提交历史
git tag                    # 看版本 tag
git diff v-a..v-b          # 对比两个版本
python tools/factor_export.py   # 因子备份（升级前必跑）
```
