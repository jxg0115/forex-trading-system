# 止损止盈重构设计方案（多维融合 · 机制矩阵 · 实时介入）

> 状态：**已确认定稿**（2026-08-27）—— 决策确认结果见文末「十章 · 决策确认记录」，实施按此执行。
> 关联模块：`oems/`（trailing_stop / smart_stop / sltp_engine）、`signal_matcher/executor.py`、
> `backtest_store/engine.py`、`market_data/market_analysis.py`、`signal_matcher/market_regime.py`、
> `indicators/technical.py`、`api/app.py`、`api/mt5.py`、`api/trading.py`、`ui_layer`。

---

## 一、目标

将现有"静态初始止盈 + 两套未执行的动态引擎"重构为：

1. **多维融合决策**：时间、行情（市场状态）、技术指标、价格结构、风控五个维度共同参与；
2. **机制矩阵灵活搭配**：移动止损止盈、阶梯止盈、分批落袋、高水位离场、时间止损、保本六个机制单元
   **并行评估、由状态门控（Gate）决定激活**，不是固定流水线串联；
3. **实时介入持有订单**：在系统主循环中周期执行，对每笔 MT5 持仓实时调整 SL/TP 或离场；
4. **回测同口径**：回测引擎使用与实盘一致的 R/ATR 公式与离场政策，使"回测验证 = 实盘执行"。

## 二、现状问题（重构依据）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 动态止盈引擎未执行 | `TrailingStopService` / `SmartStopEngine` 仅在 `api/mt5.py:94-95` 实例化，项目代码无周期性 `.update()` 调用 | 移动止损/阶梯/分批/高水位**实际不生效**，只有开仓时 MT5 端初始 SL/TP 在工作 |
| 2 | 回测与实盘止盈口径不一致 | 回测 `engine.py:88`：`take = entry ± stop_dist × tp_mult`（默认 2.0×3.0=**6.0 ATR**）；实盘 `executor.py _take_distance`：`take = atr × take_atr_mult`（**3.0 ATR**） | 回测验证的策略上实盘止盈距离只有一半 |
| 3 | 两套功能重叠的动态引擎 | TrailingStopService（ATR 三阶段+高水位+分批）与 SmartStopEngine（多规则+AI+阶梯）各有一套配置与表单 | 双配置、双表单、行为难预期 |
| 4 | 单位混用 | `hw_*`/`pc_*`/`ladder_tiers` 用美元档位，初始 TP 与移动距离用 ATR/点数 | 账户规模/波动变化时档位失配 |
| 5 | 静态学习库过拟合风险 | `sltp_engine.learn()` 用历史中位数产出 `suggested_take_pct` 且默认"形态优先" | 静态中位数套未来，存在滞后与过拟合 |

## 三、核心模型：机制矩阵 + 状态门控（非流水线）

### 3.1 五维输入

| 维度 | 数据来源 | 说明 |
|---|---|---|
| 时间 | 持仓根数/分钟/时段（亚洲·欧洲·美洲） | `smart_stop._bars_since_entry` 思路扩展 |
| 行情 | `MarketAnalysisEngine.analyze()`（趋势方向/ADX/波动/量能/环境评分） | 与 `/api/market/analysis`、行情过滤门**同一口径** |
| 指标 | `indicators/technical.py`（RSI/MACD/BOLL/ADX 现成） | 超买超卖、背离、柱转向、布林触碰 |
| 结构 | 极值、swing 高/低、支撑压力位 | 现有三阶段追踪逻辑抽取为基线 |
| 风控 | 硬止损、单笔亏损封顶、日亏损熔断 | 已有 `equity_guard` 衔接 |

### 3.2 六个机制单元（各自独立 Gate）

> 单元 = { 动作能力, 参数, gate(时间/行情/指标) }。每轮**并行评估**，gate 满足才激活并输出候选动作；不满足则本轮旁观。

| 单元 | 激活条件（Gate 示例） | 输出动作 |
|---|---|---|
| 移动止损止盈 | 盈利达标（0.5R）或已触 TP；可加行情门"强趋势才追踪" | 追踪底线价 / TP 随极值上移 |
| 阶梯止盈 | 盈利达档位 × 行情门（ADX 延续、非震荡） | 档位底线价（只进不退） |
| 分批落袋 | 盈利达档位 × 指标门（震荡市/RSI 超买/MACD 转向） | 分档平仓比例 |
| 高水位离场 | 峰值存在 × 回落超容忍（波动自适应） | 全平 |
| 时间止损/进阶 | 超时未达标（bars_held > N） | 收紧或全平 |
| 保本 | 盈利 ≥ 0.5R | SL → 成本 + 缓冲 |

### 3.3 融合规则（无顺序，只看激活集合）

1. **底线类**（移动底线 / 阶梯底线 / 保本底线）→ 取**最有利**一条作为新 SL；
2. **TP 类**（移动 TP 上移）→ 取**最谨慎**（防追高后回落）；
3. **离场类**（分批比例 / 高水位 / 时间）→ 按保守优先级**只触发最优先**的离场动作：
   风控 > 时间 > 高水位 > 分批（避免多单元同时平仓打架）；
4. **方向约束**：SL 只能朝有利方向移动（沿用 `_better_stop`）；
5. 每轮动作带冷却，并写 `last_updates` 供前端展示"本轮哪些单元被激活、为什么"。

### 3.4 灵活搭配示例（非流水线的体现）

- **趋势跟随组合**：移动（门=强趋势）+ 阶梯（门=ADX 延续）+ 高水位 —— 无分批，让利润奔跑；
- **震荡收割组合**：分批（门=震荡市）+ 保本 + 时间止损 —— 无移动追踪；
- **全机制保守组合**：全部开启，门控按指标自动切换（强趋势时只激活移动+阶梯；RSI 超买时只激活分批+高水位）—— **随指标状态自动更换搭配**。

## 四、扫描周期与实时执行链

### 4.1 执行接入

`_system_loop` 中新增 `sltp_manager.update()` 独立计时器（与 matcher 15s **解耦**）。

### 4.2 扫描周期（统一心跳 + 波动自适应）

| 项 | 默认 |
|---|---|
| 基础心跳 | 5s（可配 `scan_interval_seconds`） |
| 波动自适应 | 高波动 5s / 中等 10s / 低波动 20s（用 `atr_percentile`） |
| SL/TP 修改冷却 | 60s（沿用） |
| 离场动作冷却 | 不设（保守事件即时响应），同轮只触发最优先离场动作 |
| matcher 扫描 | 15s（不变，独立） |

> 原则：**扫描可密、动作受冷却节流、离场即时**。行情越剧烈评估越密 —— 扫描周期本身由行情维度驱动。

### 4.3 每轮流程

```
update(policy, market_analysis)
  拉取 MT5 持仓（BUY/SELL）
  逐单：
    组装五维状态（时间/行情/指标/结构/风控，行情与指标走缓存）
    并行评估六单元 → 激活集合
    融合 → {新SL, 新TP} 或 {离场动作}
    动作冷却检查 → orders.modify_position / close_position
  写 last_updates（单元激活原因 + 动作），供前端
```

## 五、与现有代码/模块的关系（映射）

| 现有机制 | 重构归宿 |
|---|---|
| `trailing_stop.py` 三阶段（激活→追踪→触TP锁利上移） | 抽取为**结构底线**，供"移动止损止盈/阶梯"使用 |
| `smart_stop.py` 规则（软/时间/阶梯/分批/关键位） | 拆为独立单元（时间单元/阶梯单元/分批单元），并入矩阵 |
| `smart_stop.py` AI 建议（keep/trail/extend/close） | 保留为**可选 L6 辅助层**（默认关闭） |
| `sltp_engine.py` 学习库（suggested_take_pct/ladder_tiers/partial_tiers） | 作为**档位初始建议来源**，单位改为 R/ATR |
| `executor._take_distance`（pattern/points/levels/ATR） | 保留为 L1 初始止盈，统一 R 公式 |
| 行情过滤门 `market_filter` + `MarketAnalysisEngine` | 引擎决策与过滤门**共用环境口径** |
| `backtest_store/engine.py` 退出口径 | 参数化：同一 R/ATR 公式 + 可选离场保护模拟 |

## 六、回测同口径

- 回测的初始 TP/SL 改用与实盘一致的公式：`R = 风险预算（risk_mult × ATR）`；`TP = min(结构目标, R × take_r_mult)`；
- 回测引擎增加离场保护模拟（高水位回落/阶梯底线），样本内验证政策参数；
- 目标：`/api/backtest/run` 的验证结果 = 实盘 `sltp_manager` 的执行结果口径。

## 八、实施阶段路线

- **阶段 0（立刻可用，最小风险）**：修复执行链 —— 把现有 `trailing_stop.update`/`smart_stop.update` 接入 `_system_loop` 周期执行，让现有动态止盈**真实生效**（行为不变，仅补执行）；
- **阶段 1（核心重构）**：`SltpPolicyConfig` + `SltpPolicyManager`（五维输入 + 六单元矩阵 + 融合），替换两套旧引擎，前端合并为单一面板；
- **阶段 2**：回测口径统一（R 公式 + 离场保护模拟）；
- **阶段 3（调优）**：行情档位联动、AI 辅助层正式化、时段策略。
